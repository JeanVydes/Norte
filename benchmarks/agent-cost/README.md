# agent-cost

What a coding agent costs on a crate it did not write, measured with the
provider's own numbers and nothing else.

The agent is handed a small, real, dependency-free crate — `Cargo.toml`,
`src/lib.rs`, `src/config.rs`, `src/main.rs`, `tests/words.rs` and `README.md` —
and three tasks of the kind a coding agent gets on someone else's code:

1. rename a public function everywhere it is used or mentioned;
2. change what a word is, and fix the test that pinned the old rule;
3. thread a flag from the command line into the config.

Nothing is written from scratch, so the agent has to read before it edits. It can
also build the crate: `cargo test --offline`, and `cargo run` when a task asks
what a line prints, through the `command` tool behind a policy that allows
`cargo` and nothing else. A compiler error comes back as a tool result, so a
change that does not build is something the model reads and fixes inside the
turn — and every round of that loop is a request the provider bills.

When the turn is over the host builds the crate on its own: `cargo test` and the
command line the tasks named, judged against what the task said it would print.
The verdict is printed beside the agent's answer, and written into the report.

## Run

```sh
export OPENROUTER_API_KEY=sk-or-...
export BENCH_ENDPOINT=https://openrouter.ai/api/v1
export BENCH_MODEL=deepseek/deepseek-v4-flash-0731
export BENCH_PROVIDER=DeepInfra          # optional: pins the upstream
cargo run -p norte-bench-agent-cost
```

| Variable | Default | Purpose |
| --- | --- | --- |
| `OPENROUTER_API_KEY` | *required* | The key for the endpoint. The variable is named after the endpoint this benchmark ships pointed at; a different endpoint reuses it. |
| `BENCH_ENDPOINT` | *required* | The `OpenAI`-compatible base `URL`. |
| `BENCH_MODEL` | *required* | The model id. |
| `BENCH_PROVIDER` | the router decides | Pins the upstream through the router, so two runs stay comparable. A routing hint, never a price. |
| `BENCH_PAUSE_MS` | `2000` | Wait before each model request, so an asynchronous provider cache can publish the previous prefix. `0` disables it. |

Nothing external is defaulted in the source: a missing variable is an error that
names it. `--help` prints this, `--report <path>` writes the report somewhere
other than `results/`, and `--jsonl <path>` writes the trail elsewhere.

The pause is part of the measurement protocol, not model time: without it, a
request fired immediately after another can miss a prefix the provider would have
cached a moment later.

## The report

Each run writes itself a markdown report under `results/`, named
`<date>-<provider>-<model>.md`:

- **The run** — when, which model, which provider, the endpoint, the budget and
  the scratch directory. The commit, the toolchain and the redacted environment
  are in the manifest.
- **Reproduce** — the environment block for that exact run.
- **Tasks** — one row per task: requests, input, cache read, hit rate, output,
  and the cost the provider reported. Then the tasks in full.
- **Tool calls** — what the agent reached for, by name, and how many of those
  calls failed. A failed call is billed like any other request.
- **The bill** — the provider's `usage.cost`, summed; per task, per request and
  per hundred tasks; the cache hit; and how many requests reported no cost at
  all, when some did not.
- **The host's check** — what `cargo test` and `cargo run` said.
- **Requests** — every request, in order, with the usage reported for it. The
  audit trail behind the totals.

Each run also writes `<stem>.jsonl` (one line per task, request, call and check),
`<stem>-tasks.csv`, `<stem>-requests.csv`, `<stem>-calls.csv`, `<stem>-checks.csv`
and a manifest beside the markdown.

The report is generated by the run that produced it, so it cannot drift from what
happened. It is not committed by hand: a report is a result, and a result is
written by the thing that measured it.

## How to read it

- **The request count is the lever.** An agent's bill is the transcript re-sent
  once per iteration, and the transcript grows with every tool result. Tokens per
  request and requests per task are the two numbers to watch.
- **The bill is the provider's.** The benchmark sums the `usage.cost` field the
  response carries. It never applies a rate, so a request whose payload carried
  no cost is named and counted rather than priced here.
- **The cache hit is read beside the bill, not used to derive one.** On an
  `OpenAI`-compatible wire the cache-read tokens are counted inside the input,
  so the hit rate is `cache_read / input` and what it was worth is already in the
  provider's number.
- **The host's check is not the agent's word.** A run whose agent said the tests
  pass and whose host says otherwise is the interesting case, and the report
  keeps both.

## Results

`results/` holds one report per run. Compare only runs that agree on model,
provider, endpoint, budget and commit.
